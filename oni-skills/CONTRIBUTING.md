# 贡献指南

欢迎补充机制、模块与故障案例。先检查已有主题，优先修正现有条目，避免多份互相矛盾的速查表。

## 写清适用条件

- 本体或《眼冒金星》、构建号、内容包、难度，以及影响机制的 Mod。
- 阶段、材料、技能、输入流量、功率和目标负载。
- 启动、控制、停机恢复、常见故障及可观察的验收条件。
- 具体出处与查阅日期；引用到文章或条目，不只放网站首页。

## 分清证据

机制数值、计算估算、作者方案和本地实测分开标注。计算注明单位、运行率和损耗；不要把理论产量写成可稳定供给人数。只看到搜索摘要、图片或旧版正文时，说明限制。

提交图纸要包含建筑层、管道层、电力层和自动化层，写清关键格子的元素、质量与材料。没有当前版本验证的精密结构，应标为待验证，不能只写“照着摆就行”。

正常生存复现优先。不得在本项目的玩法验证中用沙盒或 Debug 刷资源；引用作者自己的测试数据时，标注它是外部证据，不冒充本地测试。长周期可靠性须记录测试存档条件、周期跨度、故障与恢复，短时运行不能替代。

## 尊重原资料

用自己的文字解释事实并链接来源，不整篇搬运语雀正文、图片、存档或 Wiki 页面。需要转载或改编第三方表达、图纸时，先确认授权及署名、许可条件；根仓库许可不自动覆盖第三方材料。

来源发生冲突时，优先查对应版本的官方更新与游戏面板，再检查条目是否过期。不能为了凑提交向 OniMods 自己提反馈；外部上游确有缺陷且目的地与授权明确时，再按根仓库要求反馈。

## 提交前检查

运行技能格式检查、检查全部本地链接和 Git 空白错误。外部访问失败要记录实际失败，不把链接存在当成内容已核实。玩法修改若未实机验证，明确列出下一次验证需覆盖的情景。
