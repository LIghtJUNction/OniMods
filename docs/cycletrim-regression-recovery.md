# CycleTrim：回收退化场景的额外开销

日期：2026-10-30。最终对照版本：`62067913a5aea4daa4a8991689c86aad261b1269`。候选源码及构建产物由[验证凭证](cycletrim-regression-recovery-validation/receipt.json)中的 SHA256 标识。

本轮减少短轨道、提前返回、持续变化的动画字段和大范围动画写入中的补丁开销。生产准入规则、基准输入、迭代次数和选项默认值保持原值。实现与回归测试已整合进 CycleTrim；下述性能结果全部来自整合后的代码。

整合期间同一 PR 新增了电路路由兼容性修复、嵌套轨道保护和三个动画变化场景。本轮保留这些改动，并以包含它们的 `6206791` 重新构建对照、重新测试。此前 `7aa5003` 对照的全部数据保存在[整合前报告](cycletrim-regression-recovery-before-integration.md)，不混入下表。

## 1. 轨道：用到索引时才建立作用域

旧补丁每次 `TryAdd` 都通过 Harmony prefix/finalizer 管理作用域；包含判断提前返回等路径也承担包装成本。新实现将 lease 保存为方法局部变量，只在满足条件的末段查询中取得它，并用注入的外层 `try/finally` 保证清理。

查询直接使用局部 lease，减少逐次读取线程本地 `Current`。普通扫描及计数留在较小的方法中；兼容检查、建表和修改恢复移到较冷的路径。调用点已经检查的空路径及长度条件不再重复检查，启用状态、空谓词和路径别名仍逐次核对。

少于六个轨道的新路径直接搜索，是原有“先扫描至少两倍路径长度，之后至少还剩四次查询”规则的推论。长度 32～4096、累计扫描量及剩余查询数的阈值没有调整。

顶层调用保持按需创建；嵌套调用先建立一个禁用索引、没有 candidate 的隔离作用域，防止回调通过 `Current` 使用父缓存。若嵌套调用后来满足索引条件，再在隔离作用域之上建立自身 lease。退出时依次弹出 active lease 和隔离作用域，在嵌套入口与出口均使父索引及其兼容检查结果失效。异常、提前返回及相同长度的列表修改均有回归覆盖。

原有两层 foreach 清理、原 `leave` 目标及分支标签保留；原 `ret` 统一经过外层清理。包含 `jmp` 或 `tailcall` 的方法形状不转换。嵌套的可索引调用最多同时持有隔离作用域和 active lease；顶层不承担这项嵌套成本。

## 2. 动画：首次变化后执行原写入，减少比较临时量

`6206791` 已经让写入 helper 在发现变化后跳过比较。本轮进一步移除逐字段 helper／引用状态传递，把原始六个字段写入块保留为直接写入路径。发现第一个变化字段后，使用已经求值的目标地址和值，跳到该字段的原 `stfld`，继续后续写入。同一次调用的后续符号直接执行原写入。

字段完全相同时仍省略相同值写入，并合并冗余脏标记。浮点比较保留位级语义，包括 NaN payload、正负零和非规格化数；两个平台目标使用同一个生产 helper：

```csharp
internal static unsafe bool SameBits(float left, float right)
{
    return *(int*)&left == *(int*)&right;
}
```

指针只访问两个四字节值参数，没有指针运算、地址逃逸或游戏存储访问。mod 和宿主测试项目均显式启用 `AllowUnsafeBlocks`。整合前对同一 helper 的宿主 JIT 观察记录了 `vmovd` 寄存器位搬运，替代逐次 union 写栈／读回；这项观察不代表 Unity/Mono 生成了相同机器码。

原地址与参数求值顺序、逐字段部分写入、异常、零／负范围、失败实例的弱键记录及两个入口共同的兼容性开关均保留。字段写入块存在内部标签、分支或其他不支持的结构时，保留原方法。新增的数组地址求值失败测试以及 `6206791` 的首次变化后写入／失败测试同时保留。

## 4. 正确性与参考构建

整合后的完整宿主回归通过 **7,358 条断言**：电力 233、存档 375、轨道 2,335、动画 4,415。原有 2,059 组轨道差分保留；新增位模式测试覆盖 1,024 组任意 32 位模式、相同模式和逐位翻转，共 3,072 条断言。嵌套作用域、原异常处理区域、部分写入和恢复行为均通过真实 Harmony 宿主执行验证。

设置／探针回归通过，包含 **70 条设置断言**。完整托管 net48 参考构建通过，**0 警告、0 错误**，使用 `IncludeOniSim=false`。参考目录实际核对了 11 个清单固定的 ONI 程序集，以及 2 个辅助编译用 Unity 模块；详见[参考核验](cycletrim-regression-recovery-validation/integrated/reference-verification.json)。

`6206791` 的电路路由保护、22 个真实 Harmony 依赖补丁案例及正向控制全部保留，其生产兼容代码、夹具和测试与该版本逐字节相同。两项源代码交叉审查没有发现阻断问题；这是 LLM 源码审查，与人工批准和实机证据分别记录。

参考程序集清单声明构建 **737790**；独立方法源码契约声明 **744825**。参考构建验证编译和接口，不能证明另一个游戏构建的运行行为。

## 5. 保留的取舍与验收边界

整合前尝试过 64 位向量比较和将电力缓存拆为两张字典。前者在大范围循环中出现退化，后者没有显示足以抵消额外保留容量的稳定收益，均未保留。实验源码差异、全部样本及原因见[历史报告](cycletrim-regression-recovery-before-integration.md)。最终电力缓存结构与 `6206791` 一致；本轮继续保留该版本的路由兼容性修复。

轨道和动画选项仍默认关闭，变更后需要重启。当前证据没有覆盖 Steam 启动的真实存档、Unity/Mono、实际 DLC／其他 mod 组合或游戏帧时间。合并前的实机验收继续要求记录提交、游戏版本、存档和选项，观察轨道构建／拆除／回环／共享路径与世界切换，以及动画外观／装备／世界切换。原有存档读写和电力视图验收也保留。

非 Harmony 改写、并发列表修改，以及兼容检查后才安装的补丁仍受既有适用范围限制。动画脏标记依赖在安装后单独被改写时，仍需重启／回退验证。本次没有通过放宽准入条件或跳过兼容保护来换取计时收益。
