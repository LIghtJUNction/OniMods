# CycleTrim：整合前的开销回收测量（历史检查点）

本报告保存整合远端 `6206791` 之前的候选和全部测量，不能代表整合后的最终源码。最终结果见[本轮报告](cycletrim-regression-recovery.md)。整合前候选可在 `7aa5003` 上应用[源码差异](cycletrim-regression-recovery-validation/pre-integration-source.patch)复现（`git apply --unidiff-zero`）。

日期：2026-10-30。对照版本：`7aa5003c23cd41a385664e684c3debf918a798a2`。

本轮针对上一轮暴露的短轨道、早期命中、提前返回、持续变化的动画字段和大范围动画写入，减少优化补丁自身的工作。生产准入阈值、既有计时夹具、输入及选项默认值保持不变。

## 1. 轨道：用到索引时才建立作用域

原补丁在每次 `TryAdd` 前后通过 Harmony prefix/finalizer 建立和清理作用域；包含判断提前返回时，也会承担这笔成本。新实现将作用域保存为方法局部变量，只在符合索引条件的末段查询中创建，退出清理由注入的 `try/finally` 完成。

查询直接使用该局部作用域，减少每次读取线程本地 `Current` 的成本。普通扫描与计数保留在较小的方法中；兼容检查、建表和修改恢复移到另一方法。调用点已经检查过的空路径及长度条件也不再重复检查。启用状态、空谓词和路径别名仍按每次查询核对。

少于六个轨道的新路径直接搜索：这是原有规则“先扫描至少两倍路径长度、随后至少还有四次查询”的推论。长度 32～4096、累计扫描量及剩余查询数的阈值均未改变。

嵌套调用即使没有建立自身作用域，也会在入口与出口使父索引失效，避免回调改变输入后留下旧答案。原有两层 foreach 清理、返回目标和异常顺序保留；新的测试覆盖了嵌套回调重新建立父索引后正常返回与抛异常的情况。

## 2. 动画：首次变化后执行原写入，消除比较临时量

原实现为六个字段调用写入 helper，每次更新引用状态，并在已经发现变化后继续比较其他字段。新实现保留一条比较路径和一条原始写入路径：发现第一个变化字段后，使用已经求值的目标地址和值跳到该字段的原 `stfld`，继续原来的后续写入。同一次调用的后续符号直接写入。

字段未变时仍省略相同值写入；这项行为在上一版已经存在。本轮收益来自减少 helper 和引用状态传递、停止多余比较，以及减少位转换中的临时内存访问。

位比较使用同一个生产 helper，同时编译到宿主和 net48：

```csharp
internal static unsafe bool SameBits(float left, float right)
{
    return *(int*)&left == *(int*)&right;
}
```

这里仅重解释两个四字节值参数，没有指针运算、地址逃逸或游戏数组访问。两个项目显式启用 `AllowUnsafeBlocks`。宿主生成代码已核对到 `vmovd` 寄存器位搬运，替代原来的逐次 union 写栈／读回；原 frame 局部变量仍可能使用栈空间。

原地址和参数求值、逐字段部分写入、异常、零／负范围、失败实例的弱键记录及两个入口共同的兼容性开关均保留。原始字段写入块中存在内部标签或分支时，补丁保留原方法。

## 3. 测量方法

本轮同时保留三个参照：未打补丁的原始夹具、重新构建的上一版 `7aa5003`、当前候选。主要增量加速比取相邻旧版／新版进程的配对比值，另外报告各自相对原始夹具的比值。历史报告的中位数不作为本轮改善幅度的分母。

最初每对样本使用新进程，默认分层 JIT 的启动与提升时机造成明显波动；这批探索样本完整保留。正式受控测量将两版的 `DOTNET_TieredCompilation` 同设为 `0`，固定 CPU 0，在共享 Linux x64 主机上串行执行。场景、预热、每批工作量及七对交错样本不变。修改测量协议的原因与时间顺序记录于[测量计划](cycletrim-regression-recovery-validation/measurement-plan.md)。另运行原有完整 CLI 基准，复核默认运行时下的表现。

驱动只反射调用已有 `Measure` 方法，计时循环仍位于原测试程序集。每个进程核对原始／补丁输出，每对进程再核对两版的校验和、方向读取、电力查询和动画复制计数；汇总要求所有预定场景和样本齐全。全部样本保留，未剔除耗时离群值。

## 4. 正确性与兼容性验证

整合前候选对应的宿主回归共 **7057 条断言**：轨道 2312、动画 4261、既有电力 109、既有存档 375。轨道继续执行原来的 2059 组差分；动画新增的任意位模式对照、相同模式及单个位翻转占 3072 条断言。设置及既有探针回归通过，包含 70 条设置断言。完整托管 net48 参考构建通过，0 警告、0 错误。

参考程序集仍为清单声明的构建 737790；独立方法源码契约声明 744825。参考构建用于核对接口和编译。宿主夹具与实际游戏运行分开记录，Steam／Unity／Mono 的真实存档验收要求保留。

## 5. 保留的尝试与取舍

- 首个动画候选将 `Vector2` 打包为 64 位比较。范围循环的生成代码出现两个 32 位存储后按 64 位读取的临时量，大范围测试反而更慢。先恢复等宽比较，再改为局部参数位转换；中间候选、差异和测量均保留。存储转发停顿是对机器码的解释假设，没有硬件计数器证据。
- 电力缓存曾尝试将主要管理器的编号表与其他管理器分开。试验没有证明足以抵消额外保留容量的稳定收益，因此本检查点的电力源码与 `7aa5003` 一致；试验补丁和样本保留。
- 原有完整基准的一次电力日志不完整，未用于统计；重新运行后核对了所有预定样本。首次参考构建因 NuGet 元数据网络访问失败，重试获取元数据后通过，构建警告门槛保持原值。
