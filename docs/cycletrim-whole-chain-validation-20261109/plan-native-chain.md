# Native update-chain validation plan

Status: fixed before candidate performance measurements, 2026-11-09.

## Question and candidate

Does reusing the liquid-pressure preparation scan reduce complete native batch latency while preserving all published and subsequent simulation state? The candidate records whether the current read snapshot contains any primary liquid, including liquid cells excluded from the implicit solver. Only when the main region and the additional native displacement rows contain no primary liquid may it omit the two following explicit liquid traversals. It changes no pressure equation, iteration limit, phase ordering, or backend selection.

The code basis is `native/src/fluid_pressure.rs`, `simulation_step_fluid.rs`, and their production caller in `simulation_step.rs`. Both CPU and GPU backends reach this CPU liquid phase. The existing pressure solver already returns before iterations when it has no faces; this experiment does not claim to introduce that behavior.

## Fixed comparison and timing boundary

- Baseline: repository main revision `f40858e`, version 0.4.11. A temporary local main checkout is fixed to this revision; the shared working main is never reset or switched.
- Candidate: exact frozen production sources, recorded by commit and SHA-256 before measurement. Other accepted changes in the same delivery, including publication revision metadata, are recorded explicitly. New revision values themselves are excluded from cross-version equality; image bytes are compared.
- The same test-only harness files and module declarations are installed in both source trees. Release Rust 1.99.1, locked offline dependencies, the same target/features and one native cell worker are used. Copies of the complete executable and source manifest are retained.
- The harness starts the actual `State::start` worker and its production `Engine::run_batch` closure. It holds a ready lease, submits the next fixed frame, releases the old lease with visibility, waits on the real worker condition variable, and calls `State::finish_prepare`.
- The measured interval includes submission, worker wakeup, commands, PreparedStep simulation, GameData grid/texture/species construction, event finalization, and the stable public Grid copy in finish_prepare. It excludes fixture construction, warmup, output comparison/serialization and shutdown. It does not include Unity, rendering, or managed scheduling.
- Readiness uses the real blocking worker wait, not the Python harness's 1 ms polling. Holding the completed lease between measured batches prevents unrelated automatic empty batches from changing the workload.

## Fixed workloads

The synthetic worlds use the same explicit element/disease tables, seed, initial cell values, region order, visibility and commands on both sides. They are not captured colony saves. Main active batches contain one frame with elapsed 0.2 seconds. Four complete batches are timed per sample after two warmup batches; a sample is their mean in microseconds per completed batch. Fixtures are recreated for every process/sample. All output observations are outside those intervals.

| Dimensions | Scenarios | Purpose |
| --- | --- | --- |
| 96 × 96 | pure gas; liquid pool; mixed gas/liquid; solid thermal; narrow/multiple regions | Active coverage and small controls |
| 256 × 384 | the same five scenarios | Larger active coverage and controls |
| 736 × 304 | pure gas; mixed gas/liquid | Main improvement and non-regression gates |
| 96 × 96 | narrow/multiple regions with elapsed 1.0 seconds | Five-substep batch control |
| 96 × 96 | empty batch; zero-time frame; zero-time frame with a material command | Publication/invalidating-command controls |

Liquid fixtures contain a real connected finite positive-mass pool and exercise the production implicit solver. Mixed fixtures retain multiple gas species plus a liquid pool. Region fixtures include nonzero min_y so the native expanded displacement strip is covered. Separate correctness trajectories run at least twenty publications to cross the fifteen-publication accumulated-flow reset; the shorter timing samples do not claim to measure the reset's amortized cost.

## Sampling and acceptance gates

Each scenario has 34 independent samples per side: seventeen alternating ABBA/BAAB blocks, each contributing two samples per side. Every sample starts in a fresh process, so static publication cadence, RNG and initialization history match. CPU affinity and worker count are fixed and recorded. No concurrent build, correctness matrix or other agent performance run is allowed during timing. Record all raw samples, median, p95, min/max, paired dispersion, process CPU time, major page faults and process peak RSS. A timed major fault marks that sample invalid; retain it and rerun the entire affected paired block without cherry-picking an individual faster observation. All failures and superseded exploratory results remain identifiable.

Acceptance is fixed as follows:

1. Every equality and correctness check passes. Any state difference rejects the candidate regardless of timing.
2. The 736 × 304 pure-gas complete-batch median wall time decreases by at least **5%** from baseline.
3. Every other scenario, including the 736 × 304 mixed scene, has at most **3%** median wall-time regression. The mixed scene is the main non-regression control.
4. No local preparation/solver timing can substitute for these whole-batch gates. Existing profile fields may explain a result but are not the acceptance metric.

Timeouts, environment interference and insufficient samples are incomplete evidence, never passes. Thresholds, fixtures and required cases are not changed after results are observed. If a structural harness error is found, preserve the invalid run, correct the error and restart the complete comparison under an explicitly amended pre-measurement plan.

## Equality and failure-path checks

Compare every completed publication, outside timing: the full Grid image and separately published arrays, five texture images as raw bytes, all twenty-nine ABI event spans in order, and OMC scalar fields plus the complete cell/species records. Ignore pointer addresses and the newly added publication revision metadata. Compare the final Engine world read/write arrays, mixtures/extras/dense species, flow and accumulated flow, RNG/tick/scan state, active masks and residual time. Canonical serialization sorts HashMap keys and writes floating-point bit patterns, preserving NaNs and signed zero. A final follow-up advancing batch validates that equal publications were not hiding divergent future state.

Targeted regressions compare the optimized entry against the original unguarded post-pressure traversal: no liquid, stale scratch after a previous liquid region, liquid only in expanded rows, zero-mass/ineligible/mixed liquid, both scan directions, zero-width/height bounds and prior flow application. Existing hydraulic conservation/reference tests remain required. Production GPU execution and Unity upload behavior have their own validation; unavailable hardware is recorded and cannot be substituted by CPU timing.

The two smaller alternating cases may regress by at most **3%**. All original control cases must also remain within their original 3% limits. They use the coarse Linux `SC_CLK_TCK` unit and are diagnostic only; they are not a same-boundary substitute for wall time. ## Candidate additions before the first retained performance matrix

Recorded at **2026-11-09 10:48:54 UTC**. The retained nineteen-case performance matrix has not started. Source review identified two additional facts in the same publication chain; they are addressed before freezing the final candidate, without changing any scenario, sample count, timing boundary or acceptance threshold above.

First, a successful batch consisting entirely of elapsed-zero frames synchronizes read after each frame's commands. It also begins with cleared flow and cannot advance physics. The end of such a command batch can therefore establish the read-synchronization proof and count its newly generated output as the first current buffer. An unchanged batch refreshes the other buffer before reuse. Batches containing positive elapsed time remain excluded, including zero/advancing frames in either order. The original 73-batch forced-recomputation trajectory is retained and extended to 139 batches with zero-command/empty/zero transitions, multi-command orderings, mixed-time orderings, changing regions, delayed visibility, nonzero accumulated flow and later advancement. This is a source-proven redundancy; it is not asserted to explain the separate managed benchmark's initial command-control regression.

Second, sunlight generation preserves pixels outside current world-offset coverage. Live offset changes can leave different historical bytes in the two output buffers, so two warmup generations alone cannot establish identical complete images. Shared presentation identity must therefore depend on an exact byte comparison of all five images at the first reuse in an invalidation epoch. The result is cached for that epoch; it is not rescanned on every reused publication. Different images retain each buffer's own generation identity, and global identity exhaustion forces revision zero. Flow comparisons preserve signed zero and NaN payload bits. A dynamic-offset negative control must demonstrate the former shared-identity failure before this correction is accepted.

The final correctness checks include the expanded forced oracle, the dynamic-history/identity regressions, all nineteen complete worker trajectories and the native suite. All extra comparison work remains inside the unchanged production timing boundaries in both the native and managed experiments. Earlier matrices and their source/protocol snapshots remain separate and are not rewritten or pooled with final samples.
