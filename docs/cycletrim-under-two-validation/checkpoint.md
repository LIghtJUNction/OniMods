# 本轮首个完整验证检查点

本检查点先确立行为与构建门槛，性能结果仍待固定协议测量。源码从 `09c496c` 增加动画整块比较与变化后的原循环续接、轨道纯整数查找、电力管理器身份哈希复用及完整补丁族检查。

## 已执行验证

- 宿主真实 Harmony 回归：轨道 2,358 项、电力 280 项、存档元数据 375 项、动画 4,894 项，共 7,907 项。
- 设置与探针回归：70 项设置断言，并执行原有 pickup/chore、安装顺序和探针计数检查。
- net48 参考构建：0 个警告、0 个错误；只编译参考程序集，没有运行游戏程序集。
- 电力负对照：独立临时工程只恢复旧四族判断，新增测试在 `InnerPrefixes metadata blocks reuse for dependencies` 失败。正实现通过同一测试。

日志、源码指纹、构建输出指纹及负对照差异均位于本目录。`candidate-bin` 是临时测试快照，不进入仓库；完整运行时依赖可按原工程重建。

## 必须区分的证据

Harmony 2.4.2 的公开元数据包含 `InnerPrefixes` 和 `InnerPostfixes`。本轮守卫检查所有公开补丁列表；这些新增族的验证使用公开 `Patches` 元数据对象。尝试通过 `AddInnerPrefix` 安装时，该固定版本在 `Infix.get_InnerMethod` 抛出空引用异常；因此没有把新增 inner 回调称为已经实际执行。既有普通 prefix/postfix 在真实查询和 11 个路由依赖上的执行测试仍全部保留。

官方 [Patch.cs](https://github.com/pardeike/Harmony/blob/a264a1bf1ce689e4589e8dcc54b1e2818602a90a/Harmony/Public/Patch.cs) 的构造函数没有初始化 `innerMethod`，与此失败相符。这个结论仅针对固定的 2.4.2 包和本次安装尝试。

动画的 JIT 文件来自自主编写的宿主夹具。它用于核对宽字段读取、原循环续接及成功路径的冷处理折叠；它不代表 Unity/Mono 代码生成或游戏帧率。带 JIT 诊断的耗时不计入正式统计。
