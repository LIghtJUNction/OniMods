# 用 OniMcp 测试 Mod，并同步改进测试工具

## 必须执行

- Mod 实机测试调用 **OniMcp** 读取状态、执行测试动作、观测结果。先查询当前服务的 tools/schema，不照抄旧工具名、参数或固定工具数量。连接与 CLI 操作见 [oni-mcp-cli](../oni-mcp-cli/SKILL.md)。
- 编译和宿主测试用于快速排错，不能代替实机验收。通过 Steam 启动游戏，确认当前进程加载的是待测版本，再运行能区分修改前后的场景。
- 测试中发现 OniMcp 不好用，**同步改进 OniMcp 源码**：例如缺少必要读数、精度不足、输出过大、参数难发现、返回成功却尚未完成、错误提示不清或无法可靠暂停。不要只记问题，也不要长期用临时脚本绕过它。
- 工具修复后，跑针对该问题的验证，构建并加载修复版，再通过实际 OniMcp 调用重跑原 Mod 场景，确认它确实解除测试障碍。用户明确停止编码时遵守该限制，并说明尚未修复项。

## 测试循环

1. 明确待验证的行为和可观察结果，记录存档、Mod 版本与必要的相机/速度设置。
2. 通过 OniMcp 暂停、读取状态、执行必要动作，短时间运行后再次暂停并核对结果。使用测试副本，不用作弊资源制造正式验收结果。
3. 数值问题读取足够精度的实际数据；视觉问题同时检查截图与底层状态。性能问题确认仿真进度、视角与运行状态，避免把暂停或少做工作称为提速。
4. 遇到障碍先分清 Mod 问题和 OniMcp 问题；属于工具的问题就在本轮修复，回到原测试验证。
5. 报告实际通过和失败的场景，区分构建、部署、运行与视觉验收；附必要证据及未完成项。

OniMcp 暂时不可用时，先修连接或服务。可用 Harness 辅助计时、自动停机和宿主测试，但不能据此跳过用户要求的 OniMcp 实机调用闭环。工具缺陷没有修好时明确保留为未完成，不声称整体验收通过。
