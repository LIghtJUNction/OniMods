# 缺氧阶段策略与模块选型

把攻略转成适合当前存档的小步计划。用户只问建议时给建议；用户已授权游玩时，将计划交给现有控制循环执行，本技能不额外授予游戏写入权限。

## 先定位瓶颈，再选模块

1. 确认本体或 Spaced Out!、内容包、难度、普通/仿生复制人数，以及用户目标。能从已有上下文确定的不用再问。
2. 只有答案取决于当前存档时才补读状态。优先聚合快照；针对瓶颈补读库存、可食用热量、气体压力/温度、通行、研究、电力或管网。没有实时状态时说明假设，不伪称实测。
3. 用 [阶段判断](references/stages.md) 选择当前目标；周期只是线索，不能按周期数强行升级。
4. 从下表只读相关参考。检查前置条件、资源收支、启动步骤、维护路径和失败信号，再选一个有现成退路的小步骤。
5. 引用具体文章，说明本存档满足和缺少什么。用户授权执行时，由控制技能做暂停、精确格子预检、dry-run 和结果复读。

## 来源纪律

参考来自大叔追云彩的[缺氧各种常用模块及数据大全](https://www.yuque.com/u25332524/ftq4u7)，整理日期 2026-10-06（Asia/Taipei，UTC+08:00；对应 UTC 日期为 2026-10-05）。这里保存的是选型提示和引用，不是原图纸副本，也不是当前版本的联合实测报告。

- 原文的某个版本、配置和难度下的结论，不能推广成所有存档的保证。先核对正文中的更新时间、内容包和限制。
- 作者标记失效、旧不推荐、仅供思路、非公开或访问受限的内容，不作为已经验证的执行方案。读到文章标题不等于读懂其接线图。
- 需要具体布局、方向、数值时打开对应原文核对图示，并用当前地图、材料与连接预检；不能凭缩略图猜格子，也不能虚构蓝图下载链接。
- 禁止用游戏内 knowledge/database/guide 或已移除的百科查询补数据；使用当前资料、静态源码或可用只读状态，并区分来源事实、计算假设和当前观察。
- DEBUG、沙盒刷物资、凭空产水产气等与本项目正常生存约束冲突的做法不进入操作配方。高压、微量气体等特殊结构也不当作开局救命设施。

## 输出与交接

普通问题几句话即可，不强制写报告。模块计划给出：当前瓶颈；推荐方案及前置缺口；一项下一步动作；可观察的成功/停止信号；对应原文链接。

例如食物告急却询问壁虎模块：先说明繁殖、孵化和产出的等待期，安排现有食物的短期补给，再讨论壁虎的长期收益。不要把理论稳定产量当成今天已到手的口粮。

执行时用当前公开工具/虚拟文件路由，先读控制技能的世界编辑参考；不要从攻略推导未经发现的 MCP 工具名。蓝图已排队、建筑已完成、模块已产出是三个不同结果。
