# OniSim：质量、温度和气体扩散实验

基线：`LIghtJUNction/OniMods@6aa40cfd71ebb33d794373f5a830b87f8eefaf01`。日期：2026-10-20（UTC）。

**这是可复现的算法候选，不是游戏发行版。部分工作负载仍然退化，本轮不应作为无条件性能改进自动推广。**
完整 OniSim 尚未整合成功；Rust 1.90.0 对基线和候选均报告 37 个既存错误，诊断信息相同。没有运行或替换游戏的 SimDLL。

## 1. 改了什么

### 质量：入队时去重，保留第一次到达的顺序

原来的 `mass_components_flood.rs` 使用跨调用复用的代数标记，**不是每次清零整个地图**。
它在出队时排除重复格子，但把每个可通行格子的下、左、右、上四个邻居再次加入队列。
新实现先检查边界、深度和本轮标记，每个合法格子只入队一次。保留下、左、右、上的顺序、
取质量的提前停止条件，以及质量、温度、病菌、事件的运算顺序。

设最多到达 K 个格子。保留的队列容量上界由 `4K+1` 降为 K；时间复杂度仍是 O(V+E)，
不是新的渐近复杂度突破。对于 depth=64，几何半径为 63，K=8065。
256×256 开放地图的冷启动累计申请量从 524342 B 降到 379166 B；队列容量 32261→8065。
标记数组不变。两版热复用均没有临时分配，不能把队列减少 75% 写成总内存减少 75%。

适用条件：本次调用在处理一个格子之前，不会从其他格子改变它的可通行性；清空当前格子后变成真空，
仍可通行。不要把入队规则直接用于会改写未处理邻格的内核。分配失败的时机不要求和原版一致。

### 温度：只缓存不随温度变化的接触系数

原实现每次相邻格或背墙换热都重算材料导热系数、隔热因子和表面积。
某些组合需要 `ln` 和 `exp`。候选在一次温度遍历内使用 64 项固定缓存。
键包括两个**有顺序**的材料 ID、两个隔热值和背墙标志；不是无序材料集合。
完整键比较使哈希碰撞只影响速度，不会错误复用。借用只读材料表并在每次遍历重建缓存，避免跨帧失效问题。
非有限结果不存入缓存。温度、热容、能量限幅、读写快照、遍历顺序和相变调用未改变。

最初 128 次查询用于探测。命中少于 32 次时，本轮剩余查询回到原计算。
这只是成本回退，不能改变结果。两种分支使用独立编译的常量参数版本。
即使如此，随机材料加随机隔热值的部分场景仍然变慢；因此保留为实验候选，不宣称普遍收益。

### 气体：无病菌时省去无效比例运算

原来的 `gas.rs::update_pressure` 每次都计算迁移比例，再乘以源格病菌数。
源病菌数为 0 时，候选直接令迁移病菌数为 0，不再计算这段除法、乘法与整数转换。
原来的有序 min/max 会把任何商（包括 NaN 和无穷）夹到有限的 [0,1]，这是零分支成立的条件。

**没有因为气体流量为零而跳过整个更新。** 后面的温度舍入、病菌清理、真空替换和事件仍然执行。
含菌气体继续原算法。并未改动气体压力公式、对角传输、置换、流量槽或扫描方向。
这不是一次完整的气体物理解法替换，收益主要来自无菌分支。

## 2. Lean 证明及其边界

`proof/Transport.lean` 使用 Lean 4.19.0 的 Std，27 个定理已实际编译。
`verify.py` 检查所有定理的名字和逻辑依赖；没有 sorry、admit、自定义公理或 native_decide。
实际依赖只有标准的 `propext`、`Classical.choice`、`Quot.sound`；不是“零公理”。

证明覆盖：二进制浮点分类模型中夹取比例的有限性及零乘积；49 位有向缓存键的界限、唯一性和哨兵不冲突；
命中、碰撞、未存储、任意回退模式下缓存值与原函数值相同；有状态、有提前停止操作的有序重放；
FIFO 待处理队列与新增队列的稳定去重；以及理想整数单位的质量和能量记账守恒。

**并未形式化整个 Rust、编译器或游戏。** 入队去重与动态 BFS 候选序列之间的对应由顺序差分测试检查；
Lean 没有证明整个可变队列的终止性或内存安全。整数守恒定理不是浮点舍入后的全图质量/能量严格守恒定理。
不验证浮点异常状态标志或未屏蔽异常；缓存复用和跳过浮点运算可改变这些标志。测试覆盖默认舍入下 FTZ 关闭/开启。

## 3. 实际源代码对照

测试不是用两个重新实现的数学模型互相比。`prepare.py` 从不可变原版和当前 native 源码生成测试模块，
直接编译 `gas.rs`、`thermal.rs` 和 `mass_components_flood.rs`。真实气体遍历从
`simulation_step_fluid.rs` 提取并仅绑定到对应版本的气体函数。
质量、病菌、元素表、数值转换和记录结构使用原项目源文件。

外层世界和事件容器是精简测试夹具。所用的三条事件写入方法及 `mark_dirty` 方法体与生产源码核对；
共享辅助源码须和基线逐字相同。此检查不能代表完整 Engine/worker/FFI。

实际执行对照次数（包括重复调用，不是独立存档数量）：

| 热更新 | 4770304 |

温度覆盖全部 65536 种隔热配对 × 16 种材料配对，分别实际执行缓存填充和再次命中。
另测材料表变化、缓存碰撞、特殊浮点和背墙事件。质量覆盖全部 512 个 3×3 障碍布局、
顺序/提前退出、随机地图、代数溢出重置与 u16 坐标边界。气体含实际压力及置换遍历的多步对照。

两种 FTZ 模式都通过。

## 4. 实测方法

AMD EPYC 9V74 虚拟 CPU，Linux x86_64，Rust 1.90.0；代码生成 opt-level=3、codegen-units=1，
没有 fast-math 或 target-cpu=native。计时固定 CPU 0，但不独占物理 CPU。完整环境和二进制哈希见
`results/environment.json`。

40 个场景，每场景 8 对 AB/BA 交替测量，共 640 个正式批次。每版先预热两次，
每个批次积累真实调用耗时至少 100 ms。还原输入状态在计时外；缓存初始化和实际组件工作在计时内。
短到数十纳秒的小额消耗用例包含不可忽视的读时钟成本，不能把小差异当作稳定的游戏收益。
每种定时工作负载先完成一次实际状态一致性检查。

热测试测量“相邻格+可选背墙换热遍历”，**不包含相变和整帧**。气体测试调用实际完整气体阶段。
质量分别报告范围搜索和实际消耗。二进制内的分配计数在计时版本关闭，分配表来自独立构建。

## 5. 复现

在仓库根目录，先安装 Rust 1.90.0 和 Lean 4.19.0，然后执行：

```sh
cd experimental/OniSim/transport-lab
python3 prepare.py
cargo +1.90.0 build --release --locked --offline
./target/release/onisim-transport-lab verify
python3 proof/verify.py
# 计时和分配属于独立任务，不作为共享 CI 的速度门槛。
taskset -c 0 ./target/release/onisim-transport-lab bench > results/raw-samples.csv
cargo +1.90.0 build --release --locked --offline --features allocation-count --target-dir target-alloc
./target-alloc/release/onisim-transport-lab alloc > results/allocations.csv
python3 summarize.py
```

没有安装 elan 时，可设 `LEAN=/path/to/lean`。没有 rustup 时用该版本 cargo 的绝对路径并省略 +1.90.0。
FTZ 辅助函数要求 x86_64。`ONISIM_BENCH_FILTER` 仅用于探索单类工作负载；正式汇总要求完整 40 场景。
