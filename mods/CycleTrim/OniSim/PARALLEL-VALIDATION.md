## 早期接入与组件证据

日期：2026-10-20。范围是原生疾病发射与疾病生长后处理，不代表完整仿真核心已完成游戏验收。

## 实际执行路径

`simulation_step::step` → `MassComponents::update_disease_emitters` →
`disease_emitters::update` → `diamond::rows`。
疾病生长仍由同一更新阶段调用 `disease::post_process_bounds`。
这两个入口已使用常驻 Rayon 线程池；最多 8 线程，可用 CPU 少于 8 时降低。
`CYCLETRIM_ONISIM_WORKERS=1` 在启动前关闭并行。配置在首次大任务时读取一次。
小于 8,192 个目标格的任务及线程池创建失败时走串行。

发射器内部按行分开写入，发射器之间等待完成并保留顺序。生长后处理按完整行带
划分任务，单格生长后直接清理该格；没有跨格依赖。窄区域只遍历指定列。
每个任务继承调用线程的 MXCSR 浮点设置，结束时恢复线程原设置。
相邻格扩散、流体、热量、命令、区域和事件的既有顺序保持串行。
线程池随进程常驻，不在每帧或每次读取存档时创建；当前加载器也保留动态库句柄。

## Lean 算法的应用边界

沿用 `lean-lab/proof/SimDiamond.lean` 的菱形扫描：把无障碍四邻域广度搜索改为
裁剪的逐行区间，不分配全图访问标记或队列。该扫描在任务开始前已接入发射器；
本次把同一个行区间计算用于并行写入，并共享串行/并行的单格疾病更新函数。
发射器之间仍可能冲突，因此没有改变它们的执行顺序。

原始证明记录为 Lean 4.19.0、34 个定理，证明搜索覆盖、无重复和独立单格更新等价。
本次没有修改 Lean 定义或证明；当前 PATH 没有 Lean 编译器，因此没有重新运行
Lean 检查器。证明不涵盖 Rayon、Rust 编译器、游戏兼容性或完整疾病模拟。

## 复现

从仓库根目录执行；依赖须已缓存才能使用离线构建。

```sh
rtk proxy env RUSTC_WRAPPER= RUSTC_WORKSPACE_WRAPPER= cargo +1.99.1 test --offline --locked --manifest-path mods/CycleTrim/OniSim/native/Cargo.toml
rtk proxy python3 mods/CycleTrim/OniSim/lean-lab/harness/run_parallel.py
rtk dotnet build mods/CycleTrim/CycleTrim.csproj -c Release -p:DistPath=/absolute/output/path/
```

`run_parallel.py` 先确认实际工作线程数和差分结果，再按 1、4、4、1 的进程顺序测量。
每个负载先预热/校准，再以 AB/BA 顺序采集 8 对 BFS/生产实现样本。
仅测 512×512、8 个发射器、深度 64 和 255 的固定组件负载；不固定 CPU 亲和性。
构造世界、启动进程和线程池初始化不在稳定状态计时中。
不要与构建或其他基准同时运行。原始 CSV、编译器、CPU、亲和性、可读的 cgroup
信息及源码 SHA-256 记录在 `lean-lab/results/parallel-benchmark.json`。
无法读取的 CPU 配额记为未知；这不是隔离 CPU 资源的实验。

## 当前组件测量

512×512 网格、8 个按序执行的发射器、深度 255。每次调用累计访问 736,472 个目标格（不同发射器允许重叠）。下面是各独立进程的样本中位数范围，单位 ms/调用。

| 实现 | 耗时范围 |
| --- | ---: |
| 归档 BFS | 22.813–25.664 |
| 菱形扫描，1 线程 | 4.385–4.496 |
| 菱形扫描，4 线程 | 0.779–0.893 |

深度 64 的小负载保持串行。数据包含当前宿主调度与频率变化；没有隔离 CPU 配额，
不能把这组组件结果当作整局加速比，也没有测量疾病生长阶段的性能或并行线程池内存。

2026-10-20 后续实测已在游戏进程观测到 4 个 Rust 工作线程，并通过单存档读写往返和短步运行；当前原生测试共 14 项。详见 [RUNTIME-VALIDATION.md](RUNTIME-VALIDATION.md)。该烟测没有升级为完整游戏兼容性验收。
