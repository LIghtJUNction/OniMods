# 下个版本：实验替换「一格一物」

当前发布的 CycleTrim 0.4.0 还没有换成这套算法。OniSim 现在仍按官方模拟的约束实现：一个格子一个元素 ID、一份质量。气体被挤走时走 `displace_gas`，实现在 `mods/CycleTrim/OniSim/native/src/gas.rs`。

下个版本要实验的是另一条路：拆掉「一格一物」，把格子改成固定的一小组分质量，用没有搜索、没有仲裁的通量更新去平流，并把这个核放到 GPU 上测。顺序不变：先加速，再兼容。

这篇是方向说明，不是验收报告。

## 要试的更新

连续混合流体在一个格子上的局部更新可以写成一条式子：

```text
M(t+1) = M(t) - dt * div(F)
```

`M` 是这个格子里各组分的质量。`F` 是交界面上的通量。相邻格子有压力差，物质就从界面流过。每个格子执行同一条向量乘加，不先问「这一格现在是什么元素」。

「一格一物」为了守住「格子里只能有一种物质」，把这件事做成了排挤：新物质进来，旧物质必须挪到另一个格子。挪不走就合流、反弹，或者直接删掉。

## 算法：从通量变成图搜索

两格之间的流动本来是局部的。一格只允许一种物质之后，流动变成了「谁把谁挤走，挤到哪」。

一滴水掉进氧气格时，氧气必须离开。左边是二氧化碳，右边是墙，上面是高压，下面还是水。引擎就得向外找一个可以接收这块氧气的格子。官方模拟和现在的 OniSim 都把这一步放在 `displace_gas`：看目标格是不是同元素或真空，不是就换方向再找。找不到时，上层逻辑还要决定是强行合并、弹回，还是丢掉质量。

一次乘法能写完的界面交换，变成带递归、回溯和大量条件的搜索。搜索深度和地图形状有关，帧时间也就跟着地图形状抖。

## 硬件：分支和抢格子

现代 CPU 的宽向量指令和 GPU 的大量线程，擅长的是同一条指令作用在连续数据上。它们怕的是每个格子走不同分支，以及这一格的写入取决于邻格抢到了谁。

| | 一格一物 | 固定组分的通量更新 |
| --- | --- | --- |
| 控制流 | 每格按元素、阶段、能否排挤走不同分支。CPU 分支预测容易失效，GPU 的 warp 会被拖成串行。 | 每个格子同一条向量乘加。 |
| 数据竞争 | 左右都想进入同一格，而这一格只能留一种物质，必须仲裁先后。多核扩不出去。 | 左右各自算出进入这一格的通量，最后累加。 |
| 内存 | 排挤沿着格子往外跳着找空位，缓存局部性很差。 | 组分质量排成连续数组，按面顺序读。 |

表面上看，4 种或 16 种组分把每格算术量乘了 C 倍。在这种布局上，做 16 次浮点乘加，通常仍快于一次预测失败的分支再加一次跨缓存行的搜索。前提是数据真的是稠密、对齐、无分支的。这个前提本身也要测，见下面的补充判断。

## 补丁：不变量会制造自己的 bug

一格一物和连续流体不一致，所以会出现一批反直觉现象：单格液体挡住极热气体、气体在瀑布一类的路径里丢失质量、两种气体在单格通道里互相堵住。官方模拟为了收场，又加了许多特判，例如极小质量直接删除、超压不再排放、某些状态不允许转换。特判越厚，主模拟线程越难留下成片的直线代码。

CycleTrim 不打算在下个版本里继续加这类特判。要实验的是换掉产生这些特判的不变量。

## 补充判断

上面是这套改造的理由。下面是实现时不能省掉的界限。

1. 一格一物同时是玩法契约。管道、建筑、覆盖层和存档都在说一个元素 ID。拆掉它，改的是模拟，也是玩家看见的世界。先加速意味着这些契约先允许坏，不是假装 UI 会自动跟着变。

2. 那条局部更新删掉的是排挤搜索，不是整个时间步。接近不可压缩的流动仍要解压力。压力步是稀疏线性系统，不是一次乘加。下个版本的赢面，是去掉 `displace_gas` 这一类控制流，不是声称整帧模拟变成一次卷积。

3. 稠密的 C 个组分适合 GPU，也会在「大部分格子其实仍是纯气体」的地图上多读 C 倍数据。实验故意用稠密布局来测量，不先写稀疏特判。稀疏特判会把分支请回来。纯格子和已经混合的格子要分开计数，不能只报一个平均数。

4. 第一轮温度先用一份混合物温度，不给每种组分各放一个温度。未知量先不要乘两次。

5. 水门、吞气和单通道互卡消失之后，会换上另一组问题：数值扩散把蒸汽抹进基地、微量气体永远消不掉、建筑仍要求读到单一元素。这些问题先记成实验结果。不在同一轮里用新的一格一物规则把它们补回去。

## 下个版本做的和不做的

做：

- 格子存储改成固定长度的组分质量。
- 用界面通量更新这些质量，不搜索空格，不仲裁谁先进入。
- 把这个核放到 GPU 上，和保留的一格一物路径对比帧时间和质量误差。

不做，至少不跟这一步绑在一起：

- 疾病、建筑工作条件和存档格式的迁移。
- 声称当前 Steam 包里的 OniSim 已经是混合流体。
- 用「和原版逐格一致」当这一轮的通过条件。通过条件是：无分支核的速度，以及质量是否还在，而不是每个格子的元素 ID 是否和官方相同。

眼下 GPU 试验只做到流体展示图像，有序的流体和传热求解还没有整段搬上 GPU。下个版本的组分平流是下一次要测的核，不是这条展示路径的改名。
