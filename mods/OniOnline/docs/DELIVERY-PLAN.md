# 联机框架交付计划

目标：OniOnline 提供开放联机框架与开发 SDK，并内置“一名玩家控制一颗星球”。美术、文案、流程和可发现性均是交付门槛。先局部测试，只有最后阶段才运行全局验收。

## 分层

- Framework：独立程序集，不引用游戏、Unity、DLC 或 PLib。负责协议、认证、准入、玩法扩展、模组清单、版本化状态与恢复策略。
- ONI adapter：负责读取合法安装的游戏与模组、原生存档、原生世界、Steam 与原生界面。按能力注册，不把具体 changelist/DLC 当成所有连接的硬门槛。
- Gameplay：通过公开 SDK 实现规则。内置一人一星球是首个正式使用者；不把具体玩法判断散落在框架与 UI。
- Presentation：原生控件、原生层级、短文案、可从殖民地 HUD 管理栏直接到达的通讯入口。不用 Web 风格灰框，不在菜单/创建/加载时展示游戏 HUD。

## 模块与完成条件

1. 核心隔离：独立库无需游戏文件可构建，开发示例只引用公开 SDK；相关局部测试通过。
2. 兼容协商：按协议、玩法、能力和模组合同判断；游戏版本/DLC 作为适配信息，不直接拒绝基础联机。未知原生能力明确不可用。
3. 入场同步：比较模组 ID、发布来源、版本和内容摘要；区分同步必需与客户端专用模组；同步未完成不得进入玩法。创意工坊走 Steam 正常订阅/下载；私人本地模组不能自动公开。
4. 状态同步：有明确的生产者/权威端、频道及 schema、快照/增量、加入恢复、撤权与断线处理；未知版本保留原数据并停止覆盖。
5. 原生界面：主菜单“浏览星系”仅浏览/加入；“新游戏 → 联机”创建。进入殖民地后，通讯入口直接在原生管理栏可用，快捷键同时可用；不在主菜单、创建或加载阶段显示。界面复用原生外框、字体和按钮；状态说明短而必要。
6. 一人一星球：真实原生星球身份持久化、每人一个有效归属、重连不复制星球、玩家保有自己的模拟；已有存档与新开局均有完整流程。
7. 最终验收：前面各模块通过之后，才进行整体协议与构建、真实客户端加入/同步/保存/重连、原生 UI 多尺寸检查与失败恢复。双设备 Steam 与同机协议夹具分别报告。

## 当前证据

- SDK 已拆为独立 .NET Standard 2.0 程序集，提供玩法注册、认证消息、原生存档槽、模组清单与快照/增量传输；独立开发者示例已经通过公开 DLL 编译和实际三端 RoomSession 测试。
- 早期 0.3.5 菜单流程实测过，但视觉被用户否决，不作为新界面通过证据。
- 当前候选的浏览页、聊天、联机类别卡和加入确认都改为复用原生控件。旧 0.4.0 的“主菜单无 HUD”不能替新候选的视觉与操作验收背书。
- 模块局部验证之后，当前提交的宿主整体回归通过 4456 条断言；其中 SDK 生命周期覆盖解绑、玩法切换和旧会话失效，玩法能力合同覆盖第三方能力声明，环境描述覆盖版本/DLC 解耦，聊天状态覆盖重连时保留 HUD 入口。多人验收采集器的 47 项 Python 检查通过。Release、探针与独立示例均已编译，探针不会进入正式 ZIP。
