# 房间就是星系：自带星球与星系间旅行

状态：玩法与实现合同，2026-10-21 更新。用户已选择从存档中带入**一个星球**，不是整个原存档星系。本文不代表当前包已经能导入、迁移或托管完整星球。

## 星图、行星发动机与异步游玩（最新决定）

用户在本轮明确选择“各星球独立暂停，互访时协调”，取代此前全房间共同暂停/倍速投票的方案。普通玩家不必为了朋友上线而停掉单机进度。

- **Online 先浏览公开星系。** 选择星系后显示航图，右侧列出玩家编号、玩家名和星球，图中用相同编号标记。点击空位预留裂隙出口，再从自己的存档选择一颗星球。没有存档时走原生选星球、世界生成和初始复制人选择流程，生成期间保留有时限的落位；新存档以后仍可继续使用。预览和预留都不冒充已经生成或迁入完整星球。
- **原生星图保留自己的入口。** 已加载殖民地通过 Z 星图和打印舱打开同一套星系功能。默认名称使用 Steam 显示名加 `'s 星系`，不能拿殖民地存档名当用户名。用户修改名称后随该殖民地保存。
- **人数由星图空间承载。** 不设置四人、八人的玩法上限，不为了等待其他人而关闭加入。星图没有空位、平台服务确实已满或本机资源不足时分别报告原因；传输缓存采用字节预算和公平调度，不能把资源预算伪装成四人限制。
- **行星发动机使用游戏原生数据库条目页。** 条目登记在数据库的故事分类中，打印舱按钮直接打开它；不另做说明弹窗。可在旧存档阅读，不占随机世界生成故事槽，不消耗打印机会，不自动选复制人。星球身份随玩家的本地存档保留，加入和离开的是主机管理的星系房间，不把它描述成原生网格中的整颗星球搬运。
- **每个联机星球有永久家乡。** HomeSystemId 和显示名跟随联机分支保存；CurrentSystemId 表示当前所处星系。家乡是返回落点，不是另一颗同时运转的副本。房主不在线、没有可访问星系或玩家只是想独处时，最新的有效星球在自己的星系继续正常本地生活。
- **到访是旅行，不是交出星球所有权。** 目的星系在线、允许入驻、版本相容并有可用落位时才正式提交。只同步有权限的地图；其他人可以驾驶火箭互访。整颗星球换星系走唯一交接记录，不复制出第二个活跃副本。
- **异步运行。** 玩家自己暂停、存档、倍速、退出，默认只影响自己负责的星球。房间成员变化不强制暂停别人。目的星球负责当地的复制人、建筑、货物和战斗；其中的外来访客随目的星球的时间推进。暂停和访问状态向受影响访客明确显示，不能把某个星球暂停说成全星系仍在实时结算。
- **互访才协调。** 出发与落地、贸易交付、火箭内部与地表交接，记录源世界时间/序号、目标世界时间/序号和唯一事件 ID。在双方本地的安全交接点提交，其他未参与星球继续运行。不要求全星系保持同一周期，不把快端未来的战斗结果提前写到慢端。
- **回家也必须守恒。** 自愿返回、被踢、房主正常关房和异常掉线分别处理。返回采用最新确认状态；源端、目标端或托管节点存在不确定交接时先冻结受影响对象、查询持久记录，不能自动启用出发前旧副本。离线前可以独立确认的本地主权世界按恢复规则返回家乡；涉及其他所有者或可信托管未交还计算权时需要完成交接，不能承诺任意断电都能无损瞬间回家。
- **断线不是逃生按钮。** 短断网优先原地重连，不自动撤回家乡、取消战斗或重置伤害。若目标星系仍在线且存在预先授权、状态完整的托管节点，沿用此前确定的离线可被攻击规则。家乡兜底用于正常迁出、目标关闭和可安全完成的恢复；没有计算节点时不声称星球还能凭空推进。
- **单机优先。** 离线能继续生活，不依赖信誉服务、其他玩家或一个常驻中央宇宙。上传、评分与匹配仍是可选后续扩展。

行星发动机是旅行的故事包装，真正执行的是世界状态与星盘归属的交接，不在原生气液物理里硬推整张网格。首版先解决可靠出发与回家，不预设巨额燃料或强迫玩家重建旧存档；资源与冷却规则以后可做房间选项。

故事文案：打印舱的使用手册里夹着一页折起来的说明书。展开后，上面写着：“本设备亦可用于调整行星位置。”下方有一行小字：请勿在行星外侧站立。

## 玩家看到的流程

房主创建并命名自己的星系。公开大厅显示星系名、房主、人数、等待中/游戏中、是否允许自带星球、游戏及模拟兼容版本。玩家不用知道 IP，也不用先加好友。星系已开始仍可申请加入；密码与可加入人数规则继续适用。

玩家选择一个本地存档、再选择其中一个星球，看到将带走的复制人、着陆火箭、资源和不能一并带走的跨星球关联。确认后创建独立的联机分支，原始单机存档不覆盖。先前在同一星系生活过的联机星球优先恢复其最新进度，不能拿旧的单机存档自动覆盖。

进入星系后，星盘显示星球名和主人。其他玩家能知道它在那里，但内部默认仍有迷雾，只有探索或授权的信息会发送。玩家使用火箭互访，既可合作，也沿用已经确定的自由对抗与默认自动回击规则。普通登陆权不等于可以拆别人家或指挥别人小人。

玩家也可以携带整个已选星球离开当前星系、申请加入另一个星系。星球迁移是有明确状态的一次交接，不是在两个星系同时放一份可玩的副本。不是把同一个存档的全部行星搬进去，也不默认做无缝全球宇宙。

第一版信任玩家自觉，不做强制中心账号、在线信誉门槛或竞技反作弊。房主的踢出与本星系封禁是管理工具，不是作弊自动判定器。

## 星系、玩家与星球分别是谁

| 对象 | 身份与责任 |
| --- | --- |
| 星系 | 稳定 SystemId、房主命名的显示名、主持节点、规则、已提交检查点。改名不改变身份。恢复同一星系不能重新随机生成 SystemId。 |
| 玩家 | 稳定 PlayerId；Steam 路径绑定已验证的 Steam 身份；LAN 的随机会话身份不冒充已验证的全球身份。昵称可以改，不当主键。 |
| 星球 | 稳定 PlanetId、联机分支 LineageId、永久 OwnerPlayerId、当前 SystemId、当前计算者 AuthorityId 与权威代次。换星系不改变所有者。 |
| 实体 | 复制人、货物、火箭等带稳定 EntityId；计算权、归属与指挥权分开。迁移时重映射本地实例编号，保留网络实体身份。 |
| 迁移 | 唯一 TransferId，关联源/目标星系、星球、检查点、代次与已提交结果。重复消息查询同一条记录。 |

现有 RoomSession.RoomId 是一次通信房间的标识，现有 ownerId:nativeWorldId 是观察地图的标识，都不能直接充当跨存档永久 PlanetId。后续的稳定身份层明确包住它们，避免宣称今天的随机房间已经有永久星系身份。

同一星系拒绝相同联机分支的重复活跃实例。没有中心登记服务时，无法保证恶意玩家没有在不相干的星系启动另一份拷贝；第一版不声称全球防复制。房主按已验证玩家身份封禁，不能只靠玩家可自行重建的 PlanetId。

## 选中星球究竟带什么

- 带入选中星球的地形、气液热、物质、建筑、储存、管网、任务、自动化、动植物、居民与状态，不只是一张网格图。
- 以导出检查点时实际在该星球的居民为准，生成明确的联机归属映射；不在这里的复制人不会凭空召回。联机星球中属于其他玩家的访客不能被重新登记成星球主人的居民。
- 已着陆、与该星球绑定的火箭和内部舱室一并处理，作为附属世界；这不算导入原存档的第二颗殖民星球。在途或停在其他星球的火箭不默认带入。
- 原存档的其他星球、无人资源点和星盘不导入。存档中的研究等全局进度拆成该玩家的进度，不无条件覆盖整个房间的研究。
- 星门、货运发射器、跨星球任务、在途乘员和跨世界引用先做依赖报告。不能可靠重映射时阻止这一笔导入，并告诉玩家要先解除什么关联，不能悄悄删对象或补一份资源。
- 模拟相关 Mod 与版本必须兼容；纯界面和语言差异不应阻止互联。首版只接纳可验证的 Spaced Out! 存档，不默默转换原版存档或擅自停用存档依赖。

普通观察者不接收完整存档、世界种子或可恢复隐藏地形的数据。将来若要让可信节点离线托管，必须事先说明该节点会持有完整可恢复状态，玩家可选择接受或取消加入。不能承诺托管电脑看不到其正在计算的隐藏数据。

## 时间和落位

新来星球保留自己的发展年龄。例如 A 已生活 800 周期，B 只有 20 周期，不把 A 退回 20 周期，也不让 B 瞬间衰老到 800 周期。两者继续使用各自的本地模拟时间，只在具体跨世界交接上建立因果顺序。

不能直接重写 GameClock 数字完成对齐。迁移合同必须逐类区分世界年龄、剩余时长、绝对截止时间和房间事件时间，并迁移日程、植物成熟、食物腐败、机器计时与在途事件。未覆盖的计时器是导入阻碍，不算默认兼容。

主持端分配不重叠的星盘位置。默认有明确的最小间距规则，避免把新星球直接塞到别人火箭或现有战斗上；不替玩家选择隐藏内部地形。实际位置分配和交通距离要在加入前显示，玩法数值后续通过实测确定。

导入数据可以在后台暂存；正式激活仅协调参与方的交接检查点。刚加入的访客先等待同步，超时取消未完成的加入。其他星球继续运行，不因新玩家下载暂停。

之前的 SharedTimeController 是全房共同暂停的实现，现已不再由实际运行时创建；其历史协议用例不构成本轮异步游玩的验收。跨世界时间与计时器迁移仍需单独实现。

## 中途加入、离开与换星系

通信加入和星球正式入驻分两步：玩家先进入大厅/观察状态，再完成星球接纳。公开房间持续可被发现，开始游戏不关闭大厅。房满、被封禁、兼容性不符或明确的规则拒绝要给出具体原因。

星球入驻顺序：申请 → 核对规则与身份 → 本地导出检查点 → 目标暂存并校验 → 预留落位和计算者 → 双方约定的交接检查点提交 → 授权可见状态同步 → 玩家就绪。未提交的副本不能推进 AI、建筑或物理。

跨星系迁移顺序：目标接纳并预留 → 源端在约定检查点冻结 → 目标暂存确认 → 持久提交迁移结果 → 源端失活 → 目标以新权威代次激活。源和目标对结果不确定时先保持冻结并查询记录，不能双方各自恢复出两颗可用星球。

退出房间与断线不同。短断线自动重连原身份和原星球，不再次导入；需要持续运转的离线星球只交给事先授权、确实具有完整恢复状态的节点。没有合格节点时明确进入受影响星球的恢复等待，不能用本机旧副本冒充托管后的最新状态。

离开前处理访客和在途事件：第一版普通自愿迁移在己方外派复制人尚未返航、外来复制人/火箭尚未完成离开或跨星球交易尚未结清时暂不提交，列出人员、位置和阻碍。星球主人与复制人主人任一方换星系，都先完成相关人员返航；不能一键吞掉别人的小人、复制货物或带走未交付的交易。这是正常离开的协调条件，不是断线时强制传送。

其他房间不在线时，保留最新已提交的旅行检查点，允许下次再申请；此时该旅行副本不继续模拟。原来的私人单机存档仍独立存在，但重新用它导入属于一条新分支，不能伪装成既有联机分支的继续。

## 访客归属、做客与帮忙

2026-10-21 用户要求：互访不设想家惩罚或奖励；朋友可以帮忙，敌人或普通客人可以不干活。以下是玩法合同，尚未接入原生复制人任务系统。

- **归属不变。** 复制人始终归原玩家；所在星球负责当地模拟，原玩家保留指挥与撤回帮忙授权的权力。所在地的房主不会因为接待、断线或换星系自动成为复制人的主人。玩家离线时也不移交所有权。
- **做客模式（默认）。** 不接当地殖民地的生产、施工、挖掘、拆除等工作；仍按自身需求处理呼吸、进食、休息和如厕。这些会真实消耗当地资源，不凭空赠送食物或氧气。只能使用所在地明确开放的设施、食物和区域，不因是访客而获得无限使用权。
- **帮忙模式（本人授权）。** 原玩家主动授予可撤销的工作委托后，目的星球按当地时间运行获准的工作。当地玩家可以安排授权范围内的任务；超出范围的任务不接。施工、挖掘、拆除和物资搬运分别授权；帮忙不默认允许拆基地、转送复制人、修改归属或带走资源。双方现有门禁和设施权限继续生效。
- **离线与撤销。** 出发前选定模式与委托范围，离线沿用已提交的设置，不因没人操作突然罢工或自动转成帮忙。撤销在目的星球确认后阻止新工作；进行中的工作在安全检查点中止，不能回滚已消耗物料或重复交付物品。
- **接待由双方决定。** 星球主人可拒绝普通访问、配置接待权限或请求撤离，不强迫朋友供养所有客人。接待确认应显示人数、模式和开放的生活资源。敌对关系不自动赋予劳动授权；自由对抗仍按既有房间规则处理，不能把普通门禁当作新增的全局 PvP 免伤。
- **想家只作叙事。** 如保留“想家”状态，只显示描述；不改士气、效率、压力、饥饿等数值，不设自动返航倒计时，不用奖励逼迫玩家帮忙。

第一版不允许相关星球在访客尚未撤离时主动分赴不同星系。将来若支持长期驻留，再单独实现双方同意的跨星系通信与合格计算节点；不能把复制人留在已失联的世界里仍显示“可控制”。强制踢出、崩溃沿用下文冻结撤离与唯一恢复规则。

## 团队星球与野外星球

团队是主动接受邀请后建立的合作关系。团队成员可以分别取得查看成员计划、发布任务、指挥获委托复制人的权限；管理团队角色不自动取得这些权限。复制人的原归属不变，团队委托可撤销，离队不把复制人、库存或星球转给其他人。资源贡献以实际交付为准，贡献提议不能凭空增加库存。

用户选择团队星球由房主负责计算。房主游戏进程仍在运行且至少一个团队成员在线时，在线成员可在授权范围内共同管理；其他成员下线不撤销已有合法计划。房主进程退出时没有计算节点，客户端不得假装继续执行。将来常驻服务器可接同一个权威接口。当前只对房主本机已加载的星球建立团队权限，客人完整星球迁入并改由房主计算仍须世界迁移验收。

未占领的野外星球由第一个完成有效登陆和占领提交的玩家拥有，竞争由计算者按提交序号判定。探索地图或下载星球信息不算占领。房主创建的星系不意味着房主自动拥有所有后来占领的星球。

占领者去另一颗星球、换星系或普通下线，都不自动把所有权还给房主。若该野外星球原本就在房主完整存档中，由房主继续模拟；命令沿用最后确认的计划、日程和委托。房主退出则存档后停止。无计算节点不能把上面的居民转成另一份可运行副本。

归还是明确的放弃/移交动作，先处理居民归属、访客、在途交易和存档检查点。不能把遗留复制人直接充公。若星系需要长期不活跃回收规则，必须在占领前公开约定，普通网络故障不能触发回收。这一段仍是设计合同，不是已完成的野外占领实现。

## 房主踢出和本星系封禁

**当前 0.3.1 已实现的范围：**房主从通信房间踢出、封禁或解除封禁，立即撤销会话消息权限与观察转发，释放玩家席位。Steam 根据传输层验证的账号拒绝同一账号用新昵称、新凭据重入；LAN 只能撤销已见过的当前房间凭据，不提供账号级防绕过。封禁最多 256 条，仅保留到本次房间关闭；永久星系身份和封禁存档尚未实现。断线通知丢失后重连也会收到撤销结果。踢出不影响对方本地单机存档。下文涉及完整星球、访客资产和持久检查点的规则仍为后续目标，不能把当前会话踢出称作完成星球撤离。

房主可以拒绝入驻、踢出指定玩家及其星球、设置本星系封禁，并写原因。普通玩家不能靠昵称伪造这项权限；主持权不等于获得修改所有者私人单机存档的权力。

踢出立即撤销新的入驻、指令和跨星球交互权限，然后在双方约定的交接检查点切走该星球的计算权与位置。踢出结果写入房间检查点；玩家重连不能撤销封禁或重放旧的加入申请。

踢出不销毁存档、不把整颗星球充公，也不自动判定对方作弊。将星球按最新可用已提交检查点放入隔离恢复状态，供所有者导出旅行副本。若最新状态不可取回，显示具体最后检查点及损失范围，不声称零回档。

被踢星球中属于其他玩家的访客、火箭和转交中的资产按原所有权保存为冻结的撤离记录，等待原玩家在有效计算节点上恢复。该应急路径不凭空生成资源或重复实体，也不承诺未经实现的自动传送。完成唯一交接前不能在源、目标同时启用。恶意客人不配合时允许先隔离，不能要求全房间无限等待他确认。

房主本身是受信任的管理者，可能滥用踢出或持有不完整检查点；本地可核对记录和将来的信誉服务不能把它变成技术上绝对公平的竞技服务器。首版定位是玩家自觉、可管理的开放联机。

## 为未来信誉服务器留的接口

不在第一版搭中心服务，不自动上传，不把第三方服务加入开房、重连、存档的必需路径。先规定稳定的数据合同，具体实现随身份与迁移层落地；以下不是已存在的可调用 API。

```csharp
// IDs are stable domain IDs; provider-specific authenticated identity is separate.
interface IReputationProvider {
    Task<ReputationResult> QueryAsync(VerifiedIdentity player, CancellationToken ct);
    Task<SubmissionResult> SubmitAsync(ReputationEventBatch batch, CancellationToken ct);
}
// Admission remains the room owner's rule; service failure is not a negative score.
interface IAdmissionPolicy {
    AdmissionDecision Evaluate(JoinManifest candidate, RoomRules rules,
                               ReputationResult optionalReputation);
}
```

ReputationResult 带 provider、schemaVersion、状态（Known/Unknown/Unavailable）、数据时间、到期时间、摘要和来源；Unknown/Unavailable 不当作低分。评分含义归具体提供者，房间不能把不同来源的数字混成同一个排行榜。

事件含 EventId、SchemaVersion、SystemId、经过核实的发起方身份、涉事方身份、可选 PlanetId/LineageId、事件种类、房间检查点、发生时间和证据摘要哈希。踢出/封禁是“房主做了这个决定”的事实，不是“已证实作弊”。申诉、撤销与更正作为关联新事件，不能只累加惩罚分。普通离线、网络故障、游戏崩溃不自动扣信誉。

未来用户明确启用上传后，使用有界、可重试的事件出站队列和 EventId 去重；异步网络不进入游戏主线程。服务超时、断网、接口升级时游戏和本地存档照常工作，按房间显式规则决定是否允许仅本地准入。服务端按认证主体验证归属，不能信任客户端自己填的 Steam ID 或自称“全局封禁”。

默认不上传原始存档、私聊、IP、世界种子、隐藏地图、Steam cookie 或访问令牌。与游戏传输凭据分离；未来端点、授权、数据可见范围和保存期限由部署时明确配置。本星系封禁当前只作用于这个星系，未来信誉服务也不能未经规则配置自动升级成全球封禁。

## 实现顺序与可验收条件

1. **当前进行中：**公开发现、等待中/游戏中列表、聊天、弱网重连、授权观察。验证真正生产的房间、转发与快照，以及原生本地暂停的独立性；宿主替身不替代原生游戏。
2. **核心前置：**CycleTrim 按世界隔离原生和 Unity 侧演算，完整世界导出/恢复、附属火箭世界与稳定实体引用；在两个真实 DLC 世界中证明只有一个计算者。当前 `CYCLETRIM-INTEGRATION.md` 描述了仍缺的边界。
3. **一个星球入驻：**支持明确的游戏/Mod 组合，在可丢弃存档逐项核对导出前后质量、实体、管网、任务、计时器和副作用；不支持的组件要失败。普通观察者收不到隐藏内容。
4. **参与方交接与中途加入：**两个真实游戏客户端，完成既有星球进度不停丢失的入驻、授权观察与参与方交接；以各世界的已确认检查点验证重连，不能把原生新建殖民地当导入成功。
5. **星系间迁移与踢出：**正常移出、拒绝入驻、冻结后断网、确认丢失、提交后源崩溃、目标崩溃、房主重启、客人不配合、访客滞留、重复命令；每个实体始终最多一份可用实例。
6. **互访与离线托管：**火箭和居民真正交接、权限、自由对抗、预授权托管与所有者返回。最后才接可选信誉提供者；没有后台服务时也能完整游玩。

弱网矩阵覆盖高延迟、抖动、限带宽、双向/单向断流、长断线、多玩家同时恢复。每次分别保留源构建、宿主测试、Unity/Mono 实机、双设备 LAN 与 Steam 双账号证据。只读星球观察通过，不等于这些完整玩法已经通过。
