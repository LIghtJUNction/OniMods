# OniOnline 历史讨论草案

状态：2026-10-20 的完整玩法设计草案，保留作决策追溯。当前 0.4.0 交付合同以 [README.md](README.md)、[docs/DELIVERY-PLAN.md](docs/DELIVERY-PLAN.md)、[STAR-SYSTEMS.md](STAR-SYSTEMS.md) 和 SDK 文档为准；本页的旧版本、入口和依赖描述不能覆盖当前实现。第一阶段已实施房间通信、聊天、模组同步和原生开局入口，具体历史实测范围见 [PHASE1-VALIDATION.md](PHASE1-VALIDATION.md)。

## 星系与自带星球的新要求

2026-10-20 用户进一步确定：一个房间就是一个由房主命名和管理的星系；玩家从自己的存档选择一个星球加入，也能携带星球前往其他房主的星系，玩家通过火箭互访。房主可以踢出星球并封禁；首版依靠玩家自觉，只预留未来可选信誉服务器接口。完整玩法与边界以 [STAR-SYSTEMS.md](STAR-SYSTEMS.md) 为准，不能把当前只读观察称作完整导入或迁移。

## 本轮时间与入口规则覆盖

最新规则见 [STAR-SYSTEMS.md 的星图与异步游玩部分](STAR-SYSTEMS.md)：原生星图作为自己的星系入口，打印舱新增“行星发动机”故事条目，家乡星系兜底。用户已明确选择各星球独立暂停、互访时协调；下文旧共同时间讨论仅保留历史上下文，不能作为当前实施要求。

## 历史已确定要求（保留原始决策记录）

- 历史草案曾要求 OniOnline 强依赖 CycleTrim，并要求《眼冒金星 / Spaced Out!》内容；当前 0.4.0 已改为按游戏构建和 DLC 能力协商，CycleTrim 与 Spaced Out! 都不是固定前置，未知原生能力安全停用。
- 新游戏类型保留原版、眼冒金星，新增 `Online`，房主必须明确选择类型。Online 使用独立联机存档类型，不静默转换普通存档。
- 主菜单新增“浏览大厅”（历史称呼；当前显示为“浏览星系”，只负责浏览和加入）；设置提供联机开关和网络配置。普通存档开关能否转换成 Online 存档，另行讨论。
- 选 Online 后先见星盘，再选自己的星球，再选初始复制人。星球上显示控制玩家的名字与标记；名字默认取 Steam 用户名，可修改。
- 房主选定星球后可复制房间码；其他人粘贴加入。房主可以独自继续，不必等满人。
- 支持局域网、IP + 端口直连、Steam P2P、自定义中转和可选房间密码。
- 每个星球同时只有一个有效计算者，是该星球数据的唯一真相源。主人在线时默认由主人电脑计算；离线时交给可信节点托管。其他电脑只读复制，不同时演算这个星球。
- 只同步接收玩家有权看到的区域。战争迷雾默认开启，其他玩家的星球位置公开，内部情况不公开。
- 每个复制人有归属星球；默认仅接受其所属玩家的操作，可配置授权。
- 复制人可通过火箭等方式登陆他人星球，可互相攻击、指定攻击目标；自动回击默认开启，可关闭。
- **默认自由对抗，允许随时主动攻击，不需要先宣战。** 用户已明确选择。建筑攻击、环境破坏与友伤细则另行讨论。
- **离线后仍可被攻击，沿用原有回击设置，允许预先授权的好友帮忙防守。** 用户已明确确认；掉线不会获得无敌、禁止新攻击或取消已有战斗。
- **各星球独立暂停与推进，只有互访、落地和跨世界交接协调参与方。** 用户本轮明确选择，取代早先全房共用时间。
- **离线星球继续运转，由可信电脑接替计算；原玩家回来后接管最新状态，其他玩家继续游戏。** 用户已确认选择继续运转，不以封存离线星球作为默认方案。具体托管节点、故障恢复和代管权限仍需细化。
- 需要多语言；本轮先准备简中、繁中、英文文案草稿。
- 测试以局域网方式进行，单机回环测试不能替代真正双端局域网游戏验收。

## 建议的进入流程

`开始游戏 → 游戏类型：原版 / 眼冒金星 / 联机 → 原生选星球与复制人 → 进入自己的殖民地 → 原生星图 → 开放星系或旅行`

选联机时检查 CycleTrim 与 DLC，原生星球准备好后才开放自己的星系；旅行时另检查双方版本与所需模拟能力。星盘上的玩家标记采用名字、颜色和形状，避免只靠颜色辨认。房间码、复制按钮、邀请状态与网络设置都作为可本地化 UI，不能烘焙在背景图内。

房间支持“等待中”和“进行中仍可加入”。建议新加入者认领预留的无主起始星球，按房间允许的开局条件生成殖民地。后加入的时间优势、初始资源和无主星球是否提前模拟仍待讨论。

房间码是连接入口，不包含密码，也不是玩家身份。局域网房间码只能在可达的网络范围内使用；无需承诺短码在离线环境下也能全球解析。

## CycleTrim 与 OniOnline 的边界（建议）

CycleTrim 提供本地模拟和优化能力；OniOnline 提供会话、玩家身份、权限、星盘、大厅、同步协议、跨星球互动和战斗规则。

需要先验证或补充的 CycleTrim 能力：

1. 按世界选择是否模拟，远程副本不运行物理、建筑、管网、任务、寻路和复制人 AI。
2. 在本地世界的安全时间步取得一致快照；跨世界交接只协调参与方。
3. 导出授权区域的首次快照与后续变化，并在远端更新只读显示。
4. 世界卸载、重载和跨星球实体交接，保留稳定实体标识。

这些是拟议能力，不是现有 API 承诺。当前工作区的 CycleTrim/OniSim 有正在进行的独立改动，不能用它的短时运行记录证明上述联机能力。未取得能力前禁止以偷偷在每台电脑上模拟全部星球的方式代替设计。

已读源码中的 `OniSimSession.NewFrame` 有区域输入，`ONISIM_CopyGridImage` 可复制原生网格映像，`OniSimSession.Save/Load` 有原生存取接口。这仅表明存在起点：尚未证明对远程世界停止全部原生与托管计算，也未证明网格映像能保存复制人、建筑任务等完整殖民地状态。详见 [CycleTrim 接入调查](CYCLETRIM-INTEGRATION.md)。

## 同步与权限（建议）

### 分开记录三个概念

| 概念 | 含义 | A 的小人落在 B 星球时 |
| --- | --- | --- |
| 归属 | 小人属于谁的殖民地 | 仍属于 A 的归属星球 |
| 指挥权限 | 谁可以发指令 | 默认只有 A，可由 A 授权 |
| 计算权 | 哪台电脑计算当地结果 | B 星球的负责电脑 |

A 发“走到这里”“攻击此目标”等意图给 B。B 核对真实身份、权限、可见性、目标状态和公共时间步，再计算并发送结果。B 不能因为负责计算就获得接管 A 小人的权限，A 也不能直接发送“B 已扣血”或修改 B 的物质数据。

每个星球保存稳定的 WorldId、AuthorityPlayerId 和权威代次；小人保存 EntityId、HomeWorldId、ControllerPlayerId。归属星球与指挥者分开，给后续移民和授权留余地，但不默认允许转移归属。

房主协调大厅、公共时钟、世界归属和跨星球交接顺序，不覆盖各星球的物理结果。联机协议同样验证房主发来的命令，不把房主身份当成接管全部星球的授权。离线托管迁移计算权，星球所有权和小人指挥权限不随之转移；可信托管节点与候补必须在故障之前确定。

各星球保留独立时间与暂停。跨星球事件携带源与目标世界的序号/本地时间，仅在参与方约定的交接点生效，其他星球继续运行。访客落地后随目的世界计算，不把暂停或倍速投票扩展到全房间。具体交接与异步规则见 STAR-SYSTEMS.md。

### 可见性

- 迷雾开：默认公开星球坐标、归属玩家和在线状态；详细数据按玩家自己的探索与授权发送。
- 迷雾关：建议允许看其他殖民地已探索区域；是否连未挖掘地下地形也揭示，需用户确定。
- “已探索但当前无视野”建议只保留最后一次见到的信息，并标记过期，避免远程实时监控。
- 同步单位是有权限的区域和对象，不是镜头范围。看向别处不能使仍在视野内的战斗停止同步。
- 分别处理地形、气液、温度、建筑、管线、容器、任务、小人状态及事件，不能从摘要、目标错误、全图寻路、随机种子或日志反推出隐藏区域。
- 不向普通观察者发完整星球存档或可还原隐藏地形的生成数据；不允许先发全图再仅用 UI 黑幕遮住。获授权的可信托管节点是例外，需要完整状态以在掉线后接续模拟。
- 所有者运行自己的完整星球，无视野区域依然正常模拟；只限制传给其他玩家的数据。
- 失去授权后停止后续数据流；已经获知的信息无法让对方电脑真正忘记。

首次进入授权区域发送快照，后续发送带世界、权威代次、时间步、序号的变化。缺包或断线后按序恢复，必要时重新获取授权区域快照。复用前必须核验快照版本，旧消息不能覆盖重连后的新状态。

### 复制人指挥与访客权限

建议把两个授权页面分开：

- **我的小人**：仅自己（默认）、指定玩家可指挥、允许执行盟友的工作任务。可以逐人覆盖，随时撤销。
- **我的星球**：按访客或盟友配置登陆、通行、设施使用、资源取用、施工、拆除和视野共享，默认只给明确同意的权限。

小人要执行 B 发布的工作，既要 A 授权接任务，也要 B 允许在该区域执行相应工作。生活自救、自动回击与正常 AI 不等于允许其他玩家指挥。授权不能静默扩展成放弃自己的管理权。

自由对抗不要求宣战。能否强行登陆、攻击建筑、挖掘、取物，需要单独规则；普通访客权限不能直接充当 PvP 无敌保护，也不能因为允许降落就等于允许管理或拆除基地。

进一步的权限默认值、任务归属和访客场景见 [权限与交互草案](PERMISSIONS.md)，仍为建议，不将其视为用户逐项确认。

2026-10-21 用户补充：做客不接当地生产工作；朋友可由原玩家授权帮忙。想家仅可作为无数值效果的状态，不设奖惩。离线保留已有模式与委托，接待者控制设施和资源的访问权限，不自动接管复制人。最新合同见 [STAR-SYSTEMS.md 的访客部分](STAR-SYSTEMS.md#访客归属做客与帮忙)，优先于较早的权限草案；原生任务过滤和迁移尚未实现。

## 火箭、访问与战斗（建议）

火箭出发时为其内部世界保留一个明确计算者，建议沿用出发方。到达后，登陆到地表的小人和货物交给目的星球计算，飞船内部世界与地表不混成两个同时有效的副本。

交接采用唯一 TransferId 和持久记录：准备 → 冻结源端实体 → 目标端暂存并确认 → 在同一公共时间步提交。确认前目标不可使用，提交后源不可使用；断线后查交接记录恢复，重复消息不会复制小人和货物。双方对提交状态不确定时保持冻结，不能各自回滚出两份可用实体。

PvP 已确定为自由对抗，玩家可以随时主动指定目标，无需宣战。自动回击默认开启，可逐人关闭。建议不因看到陌生人就自动主动攻击，以免误触发冲突；自动主动索敌、友伤、停火、追击范围与是否优先逃生仍待讨论。目标必须在可知范围，不能根据隐藏实体 ID 发起攻击。

战斗所在星球统一结算路径、距离、命中、伤害、死亡与资源结果。恶意矿挖、放水、断氧也可能成为攻击，需要和直接打人一起讨论，不能只控制攻击按钮。

## 断线、存档与信任边界

用户要求考虑 3–4 人很难持续同时在线的实际情况，参考《文明六》，并明确确认离线星球继续运转。其余玩家继续游戏，原玩家回来接管原来的星球。当前异步规则取代共同时间投票：掉线不能暂停其他星球，返回家乡或托管恢复需要最新确认状态。

《文明六》官方英文手册第 163 页明确说明自动重连，以及房主离开后尝试迁移主持权。这里仅借鉴该连续游玩的方向，不把其实际游戏实现当成 OniOnline 的现成功能，也不据此承诺 AI 接管细节。

- [Civilization VI 官方手册](https://downloads.2kgames.com/civilization/vi/manuals/eu/CIV_VI_25TH_ONLINE_MANUAL_ENG.pdf)

已确定区分“星球永久归属”和“当前由谁负责计算”；以下是具体实施建议：

1. 在线时仍由星球主人计算，只有一个有效计算者。
2. 房间开始前选择可信托管节点，例如房主或玩家指定的在线伙伴；持续复制足以恢复的完整状态及已提交事件，而不是掉线之后才请求数据。需评估多人掉线后剩余节点的模拟负载。
3. 确认掉线后，在一致时间步完成计算权交接，再由托管节点继续。可以短暂等待重连或完成交接，不要求全房间无限等待。
4. 托管默认沿用既有任务、日程和自动化，不自动产生扩建、外交或进攻决策。托管计算不等于其他玩家取得该殖民地的人工指挥权限。是否增加保守自救策略、指定好友代管或完整 AI，待用户决定。
5. 原玩家回来先接收最新状态，然后在交接点恢复计算；不能把离线前的旧存档覆盖托管期间的进度。
6. 房主也可能掉线，因此房间协调状态与星球模拟状态都需要指定接任者。没有可用完整状态或无法安全选出唯一计算者时，应明确显示恢复失败并限制受影响交互，不能偷偷双端各算。

继续运转和可信托管的方向已经用户确认，具体实施方案尚未实现。原先“始终只能由主人电脑计算”的限制调整为“同一星球同时只有一个有效计算者”，并给可信托管节点完整数据的例外。普通观察者依然只接收授权可见区域；但执行托管的电脑必须持有完整星球数据，无法保证其操作者在技术上绝对看不到隐藏信息。不能声称加密存档或 UI 黑幕解决了运行中的托管数据访问。

封存离线星球不是用户选定的默认方案。若将来增加该房间规则，需要另定公共时间、往返火箭、访客和战斗规则，不能假称封存期间仍在持续同步模拟。

离线战斗规则已确认：离线后仍可受到新发起的攻击，已有战斗继续，沿用离线前的小人回击设置；预先授权的好友可在原授权范围内帮忙防守。掉线不会赋予无敌、取消伤害或重置实体，托管程序不能擅自打开主人已关闭的回击设置，也不能临时扩大好友权限。掉线检测、交接超时和接管仲裁的技术细则尚未实现。

P2P 的运行边界：仍需至少一个有能力、有完整恢复状态的在线计算节点。最后一个节点关闭后不会凭空继续模拟；正常退出需提交一致检查点，异常退出只能从可用检查点恢复。是否另提供常驻服务进程，后续讨论。

房主保存房间规则、世界归属、公共时钟和交接记录，各星球及获授权托管节点保存恢复所需状态。恢复必须对齐同一个已提交检查点，不能混合各玩家任意时间的存档。

各玩家电脑是自己星球的真相源，意味着无法防止该玩家篡改自己的计算结果；密码、权限校验和传输加密不构成竞技反作弊。建议第一版定位可信好友联机，是否支持公开竞技另行讨论。

## 网络与多语言

- 局域网与 IP 直连：优先原型，发现、认证、密码、连接与游戏状态同步分开验证。
- Steam：大厅用于房间发现，P2P 用于游戏数据；需检查游戏自带 Steamworks 接口及 Mod 场景实际可用性。不要为取得接口替换 ONI 的 AppID 或假定拥有开发者权限。
- 自定义中转：独立配置端点和传输适配，不能把“任意服务器地址”直接填入 Valve SDR 当作已有功能。
- 三种网络路径共用身份、权限和游戏协议，不能从 Steam 切换到 LAN 后绕过身份验证。显示昵称不用作身份主键；LAN 重连身份方案另行实现。
- 错误、菜单、权限、投票和战斗提示使用稳定翻译键；网络发送键和参数，由每端按自己的语言显示。未知语言回退英文，初期覆盖简中、繁中和英文。

官方资料核对于 2026-10-20，只证明 API 设计，不证明 OniOnline 可用：

- [ISteamNetworkingSockets](https://partner.steamgames.com/doc/api/ISteamNetworkingSockets)：IP socket、P2P 与 Valve 网络的使用条件。

## 分步验收

1. CycleTrim 能只推进一个负责的世界，远程世界与复制人完全不重复计算；验证加载、暂停、保存及重载。
2. 两个真实 ONI 客户端通过 Steam 启动，用局域网直连完成身份认证、星球认领、各管一星和只读查看。若只有一台机器，仅能先做传输/协议测试，双机验收明确保留。
3. 校验本地暂停独立、互访参与方协调、重连及已提交检查点恢复。
4. 在接收端检查实际数据，确认迷雾区域未发出；验证权限撤销、非法命令和旧消息拒绝。
5. 火箭登陆、返程、跨星球工作、掉线中的交接恢复，不复制或丢失小人和货物。
6. 指定攻击、默认回击和关闭回击，所有参与端结果一致；战斗中强制断线后已有攻击和新攻击仍可结算，托管沿用回击设置，授权好友可防守而未授权玩家不能借机接管。
7. 大厅、房间码、Steam P2P、自定义中转各自实测；局域网通过不能代替这些功能通过。
8. 简中、繁中、英文 UI 实际检查换行、缺字、回退与不同语言玩家互联。

上述完整玩法验收仍未执行。用户已要求优先完成第一阶段的通信、大厅、文字聊天和原生开局入口，之后再落实本文件中的具体玩法。
